我们在本项目中将“子图”标准化为：可调度子图实例 = 计算图模板（ComputeDAG 模板/结构哈希）+ 具体形状（shapes）。它在TVM/AutoScheduler 中对应唯一的 workload_key。
  - “调度任务”（SearchTask）= 子图实例 + 目标后端（target.kind）(+ 硬件参数、权重等运行上下文)。它是“在哪个后端上对这
    个子图实例做调度搜索”的最小单位。
  - dump_network_info 产生的 .task.pkl 是“某个网络在该 target 下的子图实例集合（SearchTask 列表）”，而不是一个单独子
    图；汇总去重后的 all_tasks.pkl 则是“全量子图实例集合”。

  层次化定义

  - Relay 子图（图层面）
      - 含义：模型在 Relay 层经算子融合后的一个可调度块（例如 conv2d+bn+relu）。
      - 产物：对应 .relay.pkl，见 README.md:1、gen/dump_network_info.py:1。
  - ComputeDAG 模板（TE/算子层面）
      - 含义：该子图在 TOPI/TE 下的计算定义及依赖骨架（不含具体尺寸）。
      - 标识：结构哈希（例如 00a059…），可认为是“模板指纹”。
  - 子图实例（本项目“子图”的标准定义）
      - 含义：ComputeDAG 模板 + 具体形状（输入/权重/偏置/输出等的尺寸）。
      - 标识：唯一 workload_key（JSON 字符串）= ["<结构哈希>", <shape_1>, <shape_2>, ...]，例如 ["00a059…", [1,1024],
        [1000,1024], [1,1000], [1,1000]]，见 gen/tensor_language.md:1、gen/make_dataset.py:102。
  - 调度任务（SearchTask）
      - 含义：在某个后端（target.kind）上对“子图实例”进行调度搜索的任务单元。
      - 标识：通常以 (workload_key, str(target.kind)) 唯一；携带硬件参数（如共享内存、warp 大小）与权重（用于调度器打
        分/优先级）。
      - 产物来源：auto_scheduler.extract_tasks，保存在 .task.pkl 与最终汇总的 all_tasks.pkl，见 gen/
        dump_network_info.py:1、gen/common.py:56。

  - …/network_info/v100/((bert_base,[1,64]),cuda).task.pkl

  - …/network_info/v100/all_tasks.pkl

  - 含义：描述调度状态的变换序列，由 TLM 模型（gen_state.py）生成。
  
常见变换类型： 
    - CHW：缓存写（CacheWrite），将张量写入本地存储。 
      - 是一种调度变换，将计算中间结果写入特定的内存层次（例如本地缓存或共享内存），而不是直接写入全局内存。
      - ["CHW", 2, "local"]：在 第二个操作符 写入本地缓存（寄存器或线程私有内存）。
      - 操作符”（Operator）通常指的是计算图（Computational Graph）中的一个节点，代表一个具体的计算操作，比如矩阵乘法（matmul）、卷积（conv2d）、加法（add）等。
      - 比如
      操作符0：矩阵乘法（matmul）。
      操作符1：加法（add）。
      操作符2：另一个矩阵乘法（matmul）。SP 2 ...表示“对第2个操作符（索引为2）执行分割操作。
      - 通过缓存写到本地内存，减少内存访问延迟，提高计算吞吐量
    
    - SP：分割（Split），拆分循环。 一种循环优化技术，将一个大的循环分解为多个嵌套的较小循环。
      - 在张量计算中，循环通常表示对张量维度（如行、列、通道）的迭代。
      - 例如，计算矩阵乘法 C = A * B（A 为 m × k，B 为 k × n），需要嵌套循环：
for i in range(m):
    for j in range(n):
        for k in range(k):
            C[i][j] += A[i][k] * B[k][j]
#for i in range(128): 表示遍历 128 个元素，SP 将其拆分为多级循环。
      - 大循环：原始循环可能覆盖整个张量维度（例如 128），但 GPU 线程数有限，单次循环可能无法充分利用并行性。
      - 小循环：通过分割（SP），将大循环分解为小块，匹配 GPU 的线程块（block）或线程束（warp）大小（例如 32 或 64），实现并行执行。
      - 例如，V100 线程块最大为 1024 线程，拆分后每个线程处理更小的数据块。
      这样做的意义是什么？
      - 提高并行效率，减少线程空闲时间。
      - 适配硬件架构，优化内存访问模式。
      - ["SP", 2, 5, 128, [1, 8, 2, 2], 1]：在操作符2，索引 5的轴，拆分因子 [1, 8, 2, 2]。
  
    - RE：重排序（Reorder），调整循环顺序。 一种循环优化技术，调整嵌套循环的执行顺序。
      - 循环顺序影响内存访问模式。GPU 更喜欢连续的内存访问（空间局部性），而原始顺序可能导致不连续访问。
      - 重排序可以优化数据复用，尤其是在缓存或共享内存中。
      - 提高内存访问效率，减少缓存未命中（cache miss）。
      在 ["RE", 2, [0, 5, 10, 1, 6, 11, 2, 7, 12, 15, 16, 3, 8, 13, 17, 4, 9, 14]] 中： 
      - 阶段 2：计算图中的某个操作阶段。
      - 索引列表 [0, 5, 10, ...]：原始循环的索引顺序（例如 [0, 1, 2, 3, ...]），被重排为 [0, 5, 10, 1, 6, 11, ...]。
      - 实现方式：TVM 会重新排列循环嵌套，例如将 for i in range(n): for j in range(m): 改为 for i in [0, 5, 10, ...]: for j in [1, 6, 11, ...]
    
    - FSP：融合分割（FuseSplit），融合后拆分循环。一种高级调度变换，先将多个相邻的循环融合（Fuse）成一个单一的循环，然后再将这个融合后的循环分割（Split）成多级嵌套循环。 
      - ["FSP", 3, 0, 1, 3]：在阶段 3 融合并拆分。
      索引 0：指定该阶段中第 0 个循环（通常对应外层循环，例如张量的批次维度或头数维度）。
      1：融合的因子，表示融合后循环的初始步长（这里是 1，意味着每个融合单元的大小）。
      3：分割的因子，表示将融合后的循环拆分为 3 级嵌套循环。
      融合的原因： 
      - 减少控制流开销：多个小循环的初始化、比较和跳转开销较高，融合后只需一个循环。
      - 提高数据局部性：将相邻计算合并，增加缓存命中率（cache hit）。
      - 例如，在 bert_base 的注意力机制中，softmax 和 scaled dot-product 可以融合，减少内存读写。
      分割的原因： 
      - GPU 依赖并行线程执行，大循环可能导致线程利用率低或内存访问不连续。
      - 分割后，循环粒度与 V100 的线程块（block）或线程束（warp，32 线程）对齐，优化并行性。
      - 例如，分割为 [2, 2, 3] 可分配给 12 个线程，每个线程处理更小的数据块。
      
    
    - CA：缓存读（CacheRead），缓存读取操作。 一种调度变换，将数据从全局内存（Global Memory）读取到较快的缓存层（如寄存器或共享内存），以供计算使用。
      - V100 的共享内存（64KB）允许多个线程块共享数据，TVM 优化块大小以避免银行冲突
      - ["CA", 2, 3, 8]：在 第2个操作符 索引为3的轴，第8个块，缓存读。
      
    
    - CHR：缓存读共享（CacheReadShared），共享内存读取。 一种特殊缓存读，将数据加载到共享内存（Shared Memory），并由同一线程块内的所有线程共享。
      共享内存：V100 每 SM（Streaming Multiprocessor）有 64KB 共享内存，线程块（block）内线程可快速访问，速度比全局内存快但比寄存器慢。
这样做的意义是什么？
      - 减少全局访问：例如，bert_base 的 12 个注意力头可共享 Q 块数据。
      - 提高效率：降低带宽压力，适合数据密集型任务。
      - 实际影响：可能在你的延迟优化中贡献了线程间数据复用的收益。
      - ["CHR", 1, "shared", [2]]：在第一个 使用共享内存。
    
    - PPT：预测点（PredictPoint），TLM 模型预测的分割点。 
      - 代表 PredictPoint（预测点），是由 TLM 模型（Tensor Language Model）预测的优化点，标记计算图中适合应用特定变换（如 SP 或 FU）的位置。
      - ["PPT"]：标记预测位置。
  
    - SPC：特殊分割（SpecialSplit），特定拆分策略。 
      - 普通 SP 拆分为 2-3 级（例如 [4, 32]），SPC 允许更多级（4 级以上），更精细地匹配硬件。
      - [1, 8, 2, 2] 设计为： 
        - i1=8 匹配 8 个 warp。
        - i2=2, i3=2, i4=4 细化内层，优化内存访问。
      内存访问： 
      - 分割后，线程访问 scores[h, i, :] 更连续，减少缓存未命中。
      并行性： 
      - 更细粒度的循环适合 GPU 的线程块和 warp 结构。
      - ["SPC", 2, 5, 128, [1, 8, 2, 2], 1]：特殊拆分。
  
    - FU：融合（Fuse），融合循环。 将多个连续或相关的循环合并为一个循环，减少控制流开销和提高数据局部性。
      - 在 ["FU", 5, [0, 1, 2]] 中：
      阶段 5：计算图中的第 5 个操作阶段（例如 bert_base 中 softmax 后的 scores * V）。
      索引 [0, 1, 2]：融合第 0、1、2 个循环（可能是多维循环，例如 h, i, j）。
for h in range(12):  # 12 个头
    for i in range(128):  # 序列长度
        for j in range(128):  # 序列长度
            output[h, i, j] = scores[h, i, j] * V[h, j, :]  # 矩阵乘法
#总迭代：12 * 128 * 128
#融合
for k in range(12 * 128 * 128):  # 总迭代数
    h = k // (128 * 128)  # 恢复 h
    i = (k // 128) % 128  # 恢复 i
    j = k % 128  # 恢复 j
    output[h, i, j] = scores[h, i, j] * V[h, j, :]
      - ["FU", 5, [0, 1, 2]]：融合索引 0, 1, 2。
      
    
    - AN：注解（Annotate），添加调度注解。 为计算图或调度添加元信息（metadata），指导后续优化或硬件映射。
      - 元信息（Metadata）：描述计算或调度的附加信息，例如标记线程绑定或存储级别。
      在 ["AN", 5, 0, 5] 中： 
      - 阶段 5：计算图中的第 5 个操作阶段（例如 scores * V）。
      - 索引 0：指定第 0 个循环（例如 h）。
      - 5：注解类型（自定义值，标记线程绑定、存储优化）。
for h in range(12):
    compute(output[h, :, :])

    - FFSP：自由融合分割（FreeFuseSplit）。 
      - ["FFSP", 3, 0, [3, 2, 1], 1, 1]：自由融合并拆分。
      FFSP 代表 FreeFuseSplit（自由融合分割），是一种灵活的融合和拆分组合，先融合多个循环，然后自由拆分为多级嵌套循环。 
      - 自由拆分（Free Split）：与固定拆分不同，FFSP 允许拆分因子不完全匹配原始循环范围，剩余部分由编译器调整。
      
    
    - TBS：线程绑定（ThreadBind），绑定线程。 用于将计算任务明确绑定到 GPU 的线程或线程块，优化调度和资源分配。
      - ["TBS"]：绑定线程块。
      
    - PRS：并行（Parallel），并行化循环。 将循环并行化，分配给多个线程或线程块执行，提高计算并行度。
      在 ["PRS", [4]] 中： 
      - 索引 [4]：指定第 4 个循环进行并行化（例如 bert_base 中 softmax 的 i 循环）。
      
  
    - PR：自动展开（Pragma），添加编译器指令。 减少控制流开销
      通过添加编译器提示（pragma），控制代码生成行为，例如循环展开。
      - 循环展开（Loop Unrolling）：将循环体重复展开，减少分支和跳转开销，提高指令级并行。
      - 自动展开（Auto Unroll）：编译器自动决定展开步数，优化性能。
      - 展开步数（Unroll Step）：每次展开的迭代次数，例如 512。
      - ["PR", 4, 0, "auto_unroll_max_step$512"]：自动展开 512 步。
